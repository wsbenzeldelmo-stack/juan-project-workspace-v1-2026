# Code Map

Use this file when you are trying to find where to make a change.

## HTML — `index.html`

Contains the sidebar, page/view markup, forms, modals and containers. The actual data displayed inside many containers is generated by JavaScript.

**Rule:** preserve existing element IDs unless you know which JavaScript references must also change.

## CSS

The CSS files are loaded in this exact order. Later files intentionally refine earlier rules.

1. `core.css` — original design system and most base components.
2. `visual-language.css` — unified V6.9 buttons/icons/modals.
3. `responsive.css` — small responsive rules.
4. `overview-assistant.css` — Overview and earlier assistant UI.
5. `management-layout.css` — management tables and fixed dashboard layouts.
6. `interactions-scroll.css` — interaction/scroll/page-entry polish.
7. `project-catalog.css` — Project Details, Deliverables and Catalog presentation.
8. `items-security-performance.css` — item selection, progress, protected actions and performance CSS.
9. `payments-invoice-urgency.css` — payment monitoring, invoice details and urgency theme.
10. `catalog-calendar-receipts.css` — seller catalog, calendar and receipt UI refinements.
11. `typography-guided-assistant.css` — final type hierarchy and JUAN Assistant page.

When possible, make new refinements in the most relevant existing file instead of creating another patch file.

## JavaScript

### `js/app.js`
The main application. Look here for:
- project/client/payment/catalog state
- LocalStorage/Supabase helpers
- navigation
- create/edit/delete operations
- render functions
- invoice calculations
- reports/calendar
- project details and deliverables

Useful search patterns:
- `function render` — UI renderer
- `function save` / `persist` — data persistence
- `openProjectDetails` — project routing
- `renderProjects` — Projects table
- `renderOverview` — dashboard
- `payment` — payment behavior
- `invoice` — invoice generation

### `js/assistant-bridge.js`
Compatibility bridge between the main app and assistant/bubble behavior.

### `js/assistant.js`
Guided JUAN Assistant topics, suggestions and controlled data-entry flow.

### `js/pwa.js`
Registers the service worker for offline/PWA behavior.

## Offline/PWA files

- `manifest.webmanifest` controls web-app name/icon/standalone metadata.
- `service-worker.js` caches app files. If you add a new required CSS/JS asset, also add it to `CORE_ASSETS`.

## OCR

The `ocr/` directory currently contains the OCR bootstrap used by the existing build. If you later bundle the full OCR runtime locally, keep those runtime files inside `ocr/` and document the version in `CHANGELOG.md`.
